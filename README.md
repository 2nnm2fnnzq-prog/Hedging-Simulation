# RISE Hedging Simulation

Version 1.0.0 · 24 September 2026 · Lucas Yang

Python code and saved results for a simulation study of contract-specific implied-volatility Black–Scholes delta, plain Heston delta, and correlation-adjusted Heston hedging. The primary outcome is mean squared terminal portfolio-minus-payoff error after transaction costs.

The frozen version-2 protocol uses 4,096 common paths in one Heston market regime. Six European calls, nine pricing-input scenarios, three fee levels, and two trading schedules give 324 conditions and 648 primary paired contrasts. Results are conditional on these settings, observed variance, and model-generated reference prices. This release adds no robustness experiments to the completed study.

## Quickstart

Use Python 3.12 or newer; the original study used Python 3.12.14 on macOS arm64. The pinned NumPy and SciPy versions require Python ≥3.12. Commands below use a macOS/Linux shell and run from the repository root.

```bash
git clone https://github.com/2nnm2fnnzq-prog/RISE-Hedging-Simulation.git
cd RISE-Hedging-Simulation
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
.venv/bin/python simulation/check_environment.py
.venv/bin/python simulation/validate_accounting.py --output outputs/validation/accounting.json
.venv/bin/python simulation/validate_paths.py
.venv/bin/python simulation/validate_pricing.py
.venv/bin/python simulation/validate_pricing_stress.py
.venv/bin/python simulation/run_study.py pilot
```

These commands check the environment, accounting, path generation, pricing, Greeks, and implied-volatility inversion, then run the 128-path pilot. The pilot produces 18 strategy summaries and 12 paired contrasts for one 63-day contract. It checks the end-to-end procedure without reproducing the full grid. Reports and new simulation data go into `outputs/`.

All quickstart checks passed in a fresh environment for this release. The regenerated pilot summary matched the archived summary exactly. [Release validation](RELEASE_VALIDATION.json) records these checks and the installed package versions; it does not claim a fresh rerun of the full study.

[requirements.txt](requirements.txt) pins the eight direct dependencies for computation, figures, and notebook review. [simulation/requirements-lock.txt](simulation/requirements-lock.txt) preserves the full historical macOS environment, including transitive packages. Keep that file: run manifests record its hash. The direct pins do not fully lock transitive dependencies or guarantee identical floating-point results on other platforms.

## Review the saved results

The release includes compact tables, figures, ledgers, validation records, and the original main-run manifest under [simulation/results/](simulation/results/). Raw paths, reference-price histories, and individual hedge errors are not bundled. They are regenerated by the run commands.

Open the saved review notebook after installing the dependencies:

```bash
.venv/bin/python -m jupyterlab simulation/02_run_and_review.ipynb
```

Its cells read the compact results and do not rerun the simulations. For review without a notebook server, execute the same cells and save their outputs with:

```bash
.venv/bin/python simulation/execute_review_notebook.py
```

This command updates the notebook file. The existing [results report](simulation/RESULTS_REPORT.md) explains the findings and limitations.

## Reproduce the full study

After completing the quickstart, run:

```bash
.venv/bin/python simulation/run_study.py main
.venv/bin/python simulation/run_study.py convergence --substeps 8
.venv/bin/python simulation/run_study.py convergence --substeps 16
.venv/bin/python simulation/run_study.py summarize-convergence
.venv/bin/python simulation/audit_results.py
```

The main run originally took about 11.5 minutes; each refinement run took about 1.6–1.7 minutes. These timings are observations from one computer, not benchmarks. The saved raw runs occupied about 190 MB. Main and refinement runs use three worker processes.

Completed runs refuse to overwrite their corresponding `outputs/` directories. Move an existing run directory aside before deliberately repeating it. The full audit requires raw outcomes from the main run and both refinement runs; the bundled compact results alone are insufficient.

To regenerate the compact tables and figures from the new runs, explicitly run:

```bash
.venv/bin/python simulation/analyze_results.py
```

This is the step that overwrites compact snapshots in `simulation/results/`; preceding computation commands write to `outputs/`. Preserve the published snapshots in a separate checkout if you want to compare them with a new run. Historical `pilot_audit.json` and `pilot_pricing_refinement.json` are archived checks; the supplied commands do not regenerate those two records.

## Design and provenance

- [Protocol](simulation/PROTOCOL.md) and [machine-readable configuration](simulation/protocol.json): parameters, scenarios, accounting, numerical checks, and uncertainty calculations.
- [Original run manifest](simulation/results/manifest.json): configuration, seeds, and source hashes.
- [Development log](simulation/DEVELOPMENT_LOG.md): numerical problems found and corrected before the completed runs.
- [Software and assistance](simulation/SOFTWARE_AND_ASSISTANCE.md): package roles, source attribution, and disclosed AI assistance.

The release retains the scientific implementation and completed version-2 results. The supplied parameters come from the source identified in the protocol; all analyzed paths are simulated. The study does not include an empirical backtest, estimated variance states, or the later proposed robustness extensions.
